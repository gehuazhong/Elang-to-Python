## 二、总体取舍

1. 使用 Python 3.11 及以上版本、PySide6、pytest。先以本机 Python 3.11.8、PySide6 6.11.1 建立基线，其他版本通过测试后再声明兼容。
2. 一个 `.uipro` 文件表示一个根窗口文档。标签页支持同时编辑多个文档，各自具有路径、选中状态、撤销栈和未保存标记。首版不提供单个项目中的多窗口编排。
3. 纯数据模型使用带类型注解的数据类，不能存放 QWidget、QColor、QFont、信号实例或其他运行时对象。持久修改统一经过命令。
4. 第二阶段选择真实控件绘制缓存与独立图元：稳定外观来自统一构建器，连续移动只更新图元位置，结束时提交模型。根代理保留为第一阶段比较实验；画布交互继续只依赖绘制适配接口，新增复杂控件须重新验证适用性。
5. 内置控件从第二阶段开始经过注册表创建。第四阶段补齐外部插件发现、兼容检查和插件管理，避免内置控件先硬编码、后续再迁移。
6. 顺序、失败提交、保存期间继续编辑、进程中断与基础 Qt 行为在本阶段验证；生产实现仍须重跑对应契约测试。每个阶段都有验收门槛，未满足条件时只允许修复该层，不叠加依赖它的新功能。
7. 先支持可视化事件连接与处理函数骨架，业务处理函数写在导出的 Python 文件中。首版不嵌入完整代码编辑器、调试器或任意脚本求值器。
8. 默认代码导出为可运行目录：稳定入口 `main.py`、用户文件 `handlers.py`、当前版本指针 `current.json`，以及 `generated/版本标识/` 内的界面文件和资源。更新只发布一个完整版本指针；启动入口仍是普通 Python 文件，不依赖设计器源码。
9. `BuildPlan` 的最小协议和按钮、标签执行路径在第二阶段建立。第四阶段扩展预览进程与完整导出能力，不再引入第二套控件属性解释规则。

## 四、用户界面与中文规范

主窗口使用 `QMainWindow`，中央为画布标签页；组件箱、属性、对象树、事件、资源和输出分别是停靠面板。右侧面板可以标签化，避免挤占画布。

菜单规划：

| 菜单 | 主要操作 |
| --- | --- |
| 文件 | 新建、打开、保存、另存为、关闭项目、退出 |
| 编辑 | 撤销、重做、剪切、复制、粘贴、删除、全选 |
| 排列 | 靠左、居中、靠右、靠上、靠下、等距分布、置顶、置底、锁定、解锁 |
| 布局 | 绝对布局、水平布局、垂直布局、网格布局、解除布局 |
| 视图 | 面板显示、网格、辅助线、显示隐藏对象、画布缩放 |
| 运行 | 预览、生成代码、运行生成代码 |
| 工具 | 设置、插件管理 |
| 帮助 | 使用说明、关于 |

核心快捷键为 `Ctrl+N`、`Ctrl+O`、`Ctrl+S`、`Ctrl+Shift+S`、`Ctrl+Z`、`Ctrl+Y`、`Ctrl+C`、`Ctrl+V`、`Ctrl+X`、`Delete`、`Ctrl+A`。编辑器输入框具有焦点时，文本编辑快捷键优先；撤销作用域由焦点上下文明确路由，避免误删画布控件。

所有界面标签、操作提示、事件显示名、日志摘要、对话框按钮和生成代码注释使用中文。类名、文件名、协议字段与代码名称可以使用英文标识符，不直接作为界面标签。

启动时加载 Qt 的中文翻译，并保留翻译器生命周期。第二阶段将该资源作为启动检查，缺失时停止启动并给出中文错误，避免运行混杂英文的界面。文件对话框使用 Qt 版本，应用自有确认按钮明确使用中文；字体和颜色编辑及生成应用的翻译初始化在对应阶段实现。

普通输出面板显示中文摘要；诊断文件保留原始异常堆栈、路径和技术标识符，便于定位问题。不会依赖自动翻译解释底层异常。

## 五、系统架构与依赖方向

数据流为：用户操作 → 交互控制器 → 命令校验与压栈 → 文档模型变更 → 变更通知 → 画布、属性面板、对象树与事件面板更新。

`ProjectModel` 是持久状态的唯一来源。选中对象、当前手势、画布缩放、滚动位置和预览窗口属于会话状态，不写入控件属性，也不进入项目撤销历史。

| 层 | 职责 | 依赖约束 |
| --- | --- | --- |
| 纯模型 | 数据类、结构校验、值转换、版本格式 | 不导入 Qt，不引用面板和画布 |
| 文档与命令 | 修改模型、撤销重做、保存点、变更通知 | 独立命令历史，文档层提供 Qt 通知 |
| 控件注册与适配 | 工厂、中文元数据、属性应用、事件与挂接 | 依赖核心契约，不引用主窗口 |
| 画布与面板 | 展示文档，收集用户意图 | 通过文档控制器提交命令 |
| 构建计划 | 校验并整理创建、属性、布局、事件、资源顺序 | 使用稳定标识符和可序列化值 |
| 运行时构建 | 将构建计划转为 Qt 对象树，支持设计与预览模式 | 不读取画布临时坐标作为数据来源 |
| 代码生成 | 将同一构建计划转为 Python 文件 | 不从现有 QWidget 反推项目 |
| 应用组装 | 窗口、标签页、操作路由、设置、生命周期 | 负责组合各模块 |

`DocumentSession` 持有只读文档快照、一个 `CommandHistory`、单调递增的会话修订号、当前状态标识、已保存状态标识和选中状态。保存服务按会话持有写锁并交付保存回执。主窗口将编辑、撤销、重做和保存路由到活动会话，不允许菜单动作绕开会话直接改模型或历史。

文档准备并校验不可变变更集后，一次提交模型和历史，再发布新增、删除、属性、几何、父级、各类顺序、连接和资源变化。准备与通知期间均禁止同步重入编辑、撤销重做及保存状态操作；准备失败保留原历史和保存票据，监听失败不回滚已经成功的文档提交。刷新期间阻断编辑信号，防止程序刷新被当成用户操作。

## 七、核心数据模型

### 7.1 基础类型

`JsonValue` 表示空值、布尔、整数、有限浮点数、字符串，以及由这些值构成的列表和字符串键字典。禁止保存非有限数值或运行时对象。

标识符使用字符串形式的 UUID。面向用户的名称和生成代码名称分开保存：名称可以是中文，代码名称是稳定、合法且唯一的 Python 标识符。重命名不改变节点标识符，也不破坏事件引用。

| 模型 | 字段与类型 | 说明 |
| --- | --- | --- |
| `Rect` | `x: int, y: int, width: int, height: int` | 逻辑像素矩形，尺寸必须为正 |
| `DesignerState` | `locked: bool, hidden: bool` | 只影响设计器，不影响运行时可见性 |
| `LayoutSpec` | `kind: str, margins: tuple[int, int, int, int], spacing: int` | 绝对、水平、垂直或网格布局 |
| `LayoutItem` | `index: int, row: int, column: int, row_span: int, column_span: int, stretch: int, alignment: str` | 布局顺序独立于对象树和层叠，行列参数按布局类型取有效项 |
| `WidgetNode` | 标识、类型、名称、父级、几何、属性、布局和设计状态，见下表 | 可视、非可视和结构节点统一建模 |
| `EventArgument` | 事件参数索引或带类型的常量 | 参数来源必须明确，不保存表达式 |
| `ParameterSpec` | `name: str, display_name: str, value_type: str` | 参数代码名称、中文名称及稳定类型键 |
| `HandlerSpec` | `id: str, name: str, code_name: str, parameters: list[ParameterSpec], description: str` | 保存处理函数签名和中文说明，不保存业务函数体 |
| `EventConnection` | `id: str, source_id: str, event: str, target: ConnectionTarget, arguments: list[EventArgument], enabled: bool` | 目标为处理函数或注册槽 |
| `ResourceRef` | `id: str, name: str, path: str, kind: str, sha256: str` | 资源身份、相对路径与内容摘要 |
| `CanvasSettings` | 网格大小、网格显示、网格吸附、辅助线显示、辅助线吸附、吸附距离 | 文档级编辑设置 |
| `CodegenSettings` | 模板标识、窗口类名、入口文件名 | 可迁移的导出参数 |
| `ProjectModel` | 格式版本、文档标识、项目名称、根节点标识、节点表、连接表、处理函数表、资源表、制表顺序、画布设置、导出设置、扩展数据 | 可完整序列化的文档 |

节点字段约定：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `id` | `str` | 不随重命名改变的标识符 |
| `type_id` | `str` | 注册的控件类型 |
| `type_version` | `int` | 该类型的属性格式版本 |
| `name` | `str` | 可编辑的中文对象名称 |
| `code_name` | `str` | 唯一且稳定的代码名称 |
| `parent_id` | `str \| None` | 父节点，根节点为空 |
| `slot` | `str` | 在父节点中的挂接位置 |
| `object_order` | `int` | 同父级、同挂接位置的对象树顺序 |
| `stack_order` | `int \| None` | 普通可视兄弟节点的前后层叠顺序，其余节点为空 |
| `geometry` | `Rect \| None` | 自由定位的矩形 |
| `properties` | `dict[str, JsonValue]` | 显式属性值 |
| `designer` | `DesignerState` | 设计时锁定及隐藏 |
| `layout` | `LayoutSpec \| None` | 容器提供的布局 |
| `layout_item` | `LayoutItem \| None` | 自身被纳入父级布局时的参数 |
| `extensions` | `dict[str, JsonValue]` | 保留的插件扩展数据 |

内部节点表使用按标识符索引的字典，磁盘上保存为稳定排序的数组。父子归属由 `parent_id` 和 `slot` 唯一定义，不再重复保存子节点数组。对象树按 `object_order`，绘制层叠按 `stack_order`，布局按 `layout_item.index`；三者表示不同语义，不互相回写。制表顺序仍由 `tab_order` 单独表示。

Qt 的子对象列表顺序会受到层叠操作影响，因此对象树不能从 `QObject.children()` 的返回顺序反推。第一版将多种顺序混用的设计在本版撤销。

`ConnectionTarget` 是判别联合：`kind="handler"` 时包含 `handler_id`；`kind="slot"` 时包含 `node_id` 与 `slot`。常量参数包含 `value_type` 和 `value`；信号参数使用从零开始的 `index`。

### 7.2 窗口、父级与坐标

根节点为 `builtin.main_window`，有且只有一个 `builtin.central_widget` 作为工作区。普通控件挂到工作区或允许接收子控件的容器，不能直接挂到根窗口充当普通子控件。

`slot` 明确表示挂接位置：`root`、`central`、`children`、`menu_bar`、`status_bar`、`non_visual`、`menu`、`action`。注册表定义各节点可以提供或进入哪些位置，并限制工作区、菜单栏和状态栏的数量。

根窗口几何尺寸表示客户区尺寸；根节点的横纵坐标表示运行时初始位置，设计场景中的画布原点独立定位。

普通控件的位置相对父容器的内容区域原点保存。属性适配器负责将其转换为 Qt 的父控件坐标。分组框的标题和边框会影响内容区域，因此不能直接把场景坐标写入 `setGeometry()`。

改变父级时先取得控件在场景中的矩形，再转换到新父容器内容坐标；父级和矩形必须由同一个命令提交。目标区域不足时显示吸附后的候选位置，不允许保存后才发生无提示的位置修正。

定时器没有几何矩形。工作区、菜单栏和状态栏的尺寸由根窗口管理，也不保存任意可拖动矩形。

### 7.3 布局与几何的权威来源

容器使用绝对布局时，子节点的 `geometry` 决定位置与尺寸。

容器启用水平、垂直或网格布局后，布局决定子控件的实际矩形；属性面板显示布局计算结果，并将直接位置和尺寸编辑设为只读。保存的原矩形仅用于解除布局时恢复自由编辑，不能覆盖活动布局。

水平和垂直布局按 `layout_item.index` 排列；网格布局使用其行列及跨度，索引用于稳定构建顺序。启用布局时从当前对象顺序初始化布局索引，之后独立修改；“置顶”只改层叠，“对象树排序”只改对象顺序，布局插入指示器只改布局项。网格单元重叠、负间距、无效跨度和重复纳入布局都会被校验拒绝。

### 7.4 必须保持的不变量

1. 根节点唯一；每个其他节点都有存在且兼容的父节点；不存在循环和失联节点。
2. 节点、资源、连接和处理函数各自的标识符唯一；用户名称和代码名称在文档内唯一。
3. 各自作用域内的 `object_order`、`stack_order` 和 `layout_item.index` 分别唯一且连续。命令只能修改其负责的顺序；父级变更需要同时更新三个明确的集合，不能用一个字段替代三种语义。
4. 可自由定位的控件具有有效矩形；非可视组件和受根窗口结构管理的组件没有自由矩形。
5. 属性值符合元数据；未知插件字段完整保留，不会在打开再保存后静默丢失。
6. 事件源、目标、处理函数和资源引用可解析；无效引用被明确报告，不自动指向同名对象。
7. 锁定节点可修改文字等内容，但不能移动、缩放、删除或改变父级；解锁本身可撤销。
8. 删除容器包括整个子树及关联连接；撤销时恢复原标识符、顺序、属性、连接和布局。
9. `properties.visible` 决定运行时可见性；`designer.hidden` 只决定是否在编辑画布显示；两者独立。
10. 会话状态、撤销历史、绝对资源来源路径和窗口实例不进入项目文件。

第一版迁移在独立副本中执行：旧 `order` 转为 `object_order`，普通可视兄弟节点用它初始化 `stack_order`，已受布局管理的节点用它初始化 `layout_item.index`。扩展字段和所有对象标识保留；原文件不直接修改，迁移前后都要验证，重复处理第二版应得到相同内容。

保存先取得该文件的写锁并捕获当前快照。资源使用 `assets/内容摘要.扩展名`，先落盘并核对摘要，已有资源不可就地覆盖。确认旧项目文件摘要未变化后，安全备份旧清单；最后用同目录暂存文件原子替换项目清单。清单是唯一发布点，中断可能留下未引用资源，但不能产生引用尚未完成资源的新项目。

同文档同一时刻只允许一个保存提交任务。保存回执绑定会话、状态标识和被写入的快照；保存期间继续编辑时，回执只更新已保存状态标识，不能把更新的当前状态标记为已保存。自动恢复使用同一提交协议，包含自己的资源副本，恢复后打开为未保存副本。详细顺序、写锁、外部修改及崩溃恢复约定见决策文档。

打开项目先在临时模型中完成解析、版本检查、引用检查及控件适配检查，通过后才创建新标签页。不会先清空当前文档再尝试解析。无法识别的未来格式拒绝写入；旧格式通过独立迁移函数逐版本转换。

缺失插件以“未知组件”占位呈现并保留原始类型、属性和连接。其余文档仍可编辑和保存；预览给出具体缺失项，代码导出在无法完整构建时停止，不能悄悄省略控件。

## 九、控件注册与属性系统

### 9.1 注册契约

`WidgetSpec` 包含稳定类型标识、类型版本、中文显示名、中文分组、实际 Qt 类、可视种类、父级规则、默认尺寸、工厂、属性定义、事件定义、槽定义、挂接适配器与代码导出能力。

`PropertySpec` 包含内部键、中文名、中文分组、值类型、默认值、存储位置、Qt 属性名或适配器、只读状态、条件只读规则、枚举选项以及值域校验。

继承公共属性后，先应用控件自己的 `property_overrides`，再添加独有属性，形成无重复键的最终定义。几何默认值必须与该控件的 `default_size` 一致；例如按钮高度为四十，标签宽度为一百六十。元数据默认值变化需提升类型版本并提供迁移规则，避免旧项目因默认值变化而无提示变样。

实例名称和代码名称由唯一名称分配器根据 `default_name`、`code_name_prefix` 初始化，不能将公共属性中的通用默认名称直接写入多个节点。

反射只核验已注册属性。不能把 Qt 的所有动态属性直接暴露，也不能将项目文件里的字符串当作任意 Python 类名执行。

简单属性通过元对象查询存在性和可写性，再使用已知映射应用。几何、字体、颜色、图片、列表条目、表格及树结构走专用适配器。适配器还定义初始化顺序，例如先设置最小值与最大值，再设置当前值。

## 十、画布与直接操作

### 10.1 渲染结构

第二阶段构建真实 QWidget 树并缓存原生控件画面，由 `QGraphicsScene` 中的独立图元合成。编辑器通过 `CanvasRenderer` 取得矩形和临时画面；文档、属性面板及命令不能引用图元或原生控件。按钮、标签已验证，复杂容器的裁剪和布局必须随第三阶段重新验收。

连续移动不在每次鼠标移动时修改 QWidget 树。第二阶段复用稳定状态已经生成的控件画面，移动期间只调整图元，释放时一次提交模型。布局、缩放手柄及复杂容器的手势合成在第三阶段实现。准备、连续绘制和最终提交分别测量，不能用连续帧很快掩盖开始或结束时的卡顿。

缓存键包含文档状态、画布缩放、设备像素比、样式及字体版本。文本、资源、父级、可见性或缩放变化使相关缓存失效；取消手势必须恢复真实控件可见性，不能把实验中的隐藏动作写进文档。跨容器移动需遵守目标裁剪，多选只抓取最上层子树，并按显式层叠顺序合成。

设计模式拦截鼠标、键盘和上下文操作，避免按钮执行、输入框获得编辑焦点、组合框弹出菜单和定时器启动。不能简单禁用整个根窗口，因为那会改变全部控件的视觉状态。

运行时隐藏的控件可以在设计模式显示带中文标记的轮廓；设计时隐藏对象通过对象树找回。菜单在设计模式使用专用编辑交互，不执行菜单动作。

`QGraphicsProxyWidget` 不适合直接承载所有自定义绘制组件。使用特殊屏幕绘制或 OpenGL 的插件必须提供设计预览替身；首版内置组件使用普通 QWidget 系列。

### 10.2 拖放创建

组件箱通过 `QDrag` 与 `QMimeData` 提供 `application/x-uiplay-widget` 数据，内容仅包括协议版本、已注册类型标识和拖动热点。解析后校验类型、父级能力与坐标，再提交创建命令。

鼠标落点经过视口、场景、父容器内容坐标转换。拖动中显示组件名称、目标容器和预览矩形；松开即创建。双击组件时，在当前可见工作区中心创建，优先使用当前选中的可接收容器。

不通过文件中的类名动态导入控件。组件类型必须已经注册。

### 10.3 手势与选择

交互状态包括空闲、准备手势、框选、移动、缩放、拖放预览、提交和取消。按下时记录快照状态标识、选中集合、起点和原始矩形；移动期间更新临时显示；释放时校验基础版本并提交一次命令；按 `Esc` 时恢复模型所定义的显示。输入捕获丢失、切换文档和预览启动也必须走统一取消路径。

`Ctrl` 点击切换选择，空白拖动框选。选择集合同时包含祖先和后代时，移动和删除只处理最上层选中节点，防止子节点被计算两次。

控件提供八个缩放手柄，遵守最小尺寸。首版八手柄作用于单个控件；多选支持整体移动、对齐和分布，多选比例缩放不是首版验收项。

保存、关闭标签或切换文档时取消尚未提交的手势，防止临时显示被误当作已经保存的数据。

### 10.4 吸附、对齐和层级

默认网格为八个逻辑像素，吸附距离为六个视口逻辑像素，并根据画布缩放换算成场景距离。Qt 的逻辑坐标与物理像素须区分，避免再乘一次系统显示缩放比例。辅助线候选优先于网格，候选来自同父容器控件及内容边界的边缘和中心。

多选移动以选中集合的外接矩形吸附，所有控件保持相对偏移。对齐按主选控件执行；等距分布固定两端，至少选择三个同父级控件。

对齐与分布首版要求同父级，条件不足时给出中文原因。锁定控件不参与几何修改。前后层叠只调整同父级普通可视节点的 `stack_order`，不改对象树或布局位置。

跨容器拖动显示目标高亮，最终由父级调整命令同时更新父级和几何。对象树拖动遵循相同规则；根节点、工作区及不兼容的结构组件禁止随意改父级。

### 10.5 复制粘贴

剪贴板保存选中子树的类型、属性、布局、内部连接和资源引用。粘贴时为节点、处理函数声明及连接分配新标识符，生成唯一名称和代码名称，再统一重映射引用。

复制时保留完整包含在子树内的槽连接。指向子树外对象的连接不复制，并显示数量提示。处理函数声明复制为新的骨架身份，不能假定外部业务代码已经复制。

跨文档粘贴复制所需资源到目标文档的暂存区并去重；资源或控件缺失时先报告，不能创建半棵子树。重复粘贴使用固定偏移，整个粘贴作为一个可撤销操作。

## 十一、命令模式与撤销重做

第二阶段使用独立 `EditCommand` 与 `CommandHistory`：纯函数构造候选模型，统一命令保留变化节点和必要元数据，文档负责准备、提交与通知。这样可以按保留数据字节数裁剪完整命令，不依赖 Qt 栈的条数限制。下表是操作职责划分，不要求为简单操作机械建立独立类。

| 命令 | 必须保存的状态 | 撤销结果 |
| --- | --- | --- |
| `AddNodesCommand` | 节点完整快照、父级与插入顺序 | 移除本次创建的节点 |
| `DeleteNodesCommand` | 子树、原始顺序、关联连接、布局与制表顺序 | 按原标识恢复全部对象关系 |
| `SetGeometryCommand` | 所有目标的旧矩形与新矩形 | 恢复原位置和尺寸 |
| `SetPropertiesCommand` | 旧值、新值及原来是否存在该属性 | 恢复显式值或恢复继承状态 |
| `ReparentNodesCommand` | 旧、新父级，挂接位置，顺序，矩形和布局项 | 原父级及显示位置一致恢复 |
| `ReorderObjectsCommand` | 对象或菜单项的旧、新 `object_order` | 恢复对象树或菜单项顺序 |
| `RestackNodesCommand` | 普通可视兄弟节点的旧、新 `stack_order` | 只恢复前后层叠 |
| `ReorderLayoutItemsCommand` | 旧、新布局索引和相关网格位置 | 只恢复布局排列 |
| `PasteNodesCommand` | 创建子树、标识重映射、处理函数、资源引用 | 移除粘贴产生的数据并保留可重做快照 |
| `SetLayoutCommand` | 布局前后定义及所有子节点布局项、矩形 | 恢复原布局方式和位置 |
| `SetConnectionsCommand` | 连接及处理函数声明的差异 | 恢复原绑定 |
| `SetResourcesCommand` | 资源清单、属性引用和暂存引用 | 恢复原资源关系 |

命令压栈前检查基础修订号，完成结构、类型及引用校验，并准备前后快照及变更集。组合操作在独立候选模型上验证后一次提交；失败必须同时保持当前状态、撤销游标、重做分支和保存标识不变。空操作不产生新历史项。

历史只接收准备完成的命令；文档将历史与当前快照一并发布。第一次提交和后续回放不能重复执行用户意图，手势预览必须与持久状态分开。

Qt 回调边界捕获异常并输出中文错误。文件读写、插件加载和代码导出等可能失败的外部操作不在命令的 `redo()` 中临时执行；先准备结果，再提交可回放的数据变更。

生产命令的 `redo()` 和 `undo()` 只切换已准备的数据及状态标识；应用级通知延迟到历史操作返回后发布。每次提交、撤销或重做都递增会话修订号，撤销恢复旧状态标识而不会倒退修订号。订阅者异常与通知期间的重入操作被隔离并记录，不污染文档事务。

视图更新失败时保留已经校验的模型和命令历史，标记受影响组件并尝试从模型重建显示；重建仍失败时显示中文占位错误。不能通过偷偷改写模型默认值来掩盖渲染失败。

连续文字或数字编辑仅在同一编辑会话、同一对象集合和同一属性内合并。切换焦点、保存和关闭会话结束合并。一次拖动、缩放、对齐或粘贴只产生一个撤销项。

未保存状态由 `current_state_id != saved_state_id` 判定，不依赖 Qt 清洁索引。异步保存旧快照成功时只更新实际写盘状态的标识；当前新编辑仍是未保存。撤销回实际保存的状态标识后显示“已保存”。

设计时锁定、隐藏以及影响文档的画布设置也经过命令；面板停靠位置、选中对象和查看缩放属于用户会话偏好，不污染项目撤销历史。

## 十二、中文事件与信号槽

每种组件仅显示其注册且经过核验的事件。事件标识与中文显示名分开，信号重载和参数类型明确保存于元数据。

| 中文事件 | 适用组件 | 实际来源 | 参数说明 |
| --- | --- | --- | --- |
| 被单击 | 按钮 | `clicked(bool)` | 是否选中 |
| 被双击 | 列表条目 | `itemDoubleClicked` | 由适配器转为条目序号等稳定值 |
| 被双击 | 通用可视控件的可选扩展 | 鼠标双击事件适配器 | 不是假定存在的 `doubleClicked` 信号 |
| 文本改变 | 单行编辑框 | `textChanged(str)` | 新文本 |
| 文本改变 | 多行编辑框 | `textChanged()` | 原信号无参数，适配器按需读取当前文本 |
| 值改变 | 滑块、进度条 | `valueChanged(int)` | 当前数值 |
| 选择改变 | 组合框 | `currentIndexChanged(int)` | 当前索引 |
| 选中改变 | 选择框、单选框 | `toggled(bool)` | 是否选中 |
| 超时 | 定时器 | `timeout()` | 无参数 |
| 被触发 | 菜单项 | `triggered(bool)` | 是否选中 |
| 窗口关闭 | 根窗口 | `closeEvent` 适配器 | 首版作关闭通知，不提供取消关闭的返回值协议 |

集合控件的条目对象不能序列化为事件参数，须由适配器转为索引、文本或约定的数据键。表格及树的事件需额外明确行列或节点路径。

事件面板先选源对象和中文事件，再选择生成处理函数骨架或连接到另一个对象的注册槽。简单槽包括“设置文本”“设置启用”“设置可见”“启动定时器”“停止定时器”。

连接参数只能选择信号参数或填写与目标参数类型兼容的常量。未选择的信号参数被明确丢弃，不依赖各信号重载的隐式兼容行为。

事件绑定在属性初始化后执行，避免初始化数值触发业务逻辑。定时器自动启动发生在绑定完成之后。预览中尚无实现的处理函数显示中文日志；已经配置的内置槽连接真实生效。

生成代码时使用稳定的处理函数名称。控件改名不会自动改写用户业务函数名。重复生成时保留 `handlers.py`；新增事件如缺少对应函数，由生成的适配入口调用中文默认处理逻辑，并在导出报告中列出待补充的签名。

## 十三、代码生成、预览与布局一致性

第二阶段先把模型快照与冻结的注册表编译成最小 `BuildPlan`，覆盖窗口、工作区、按钮和标签。计划包含协议版本、源状态标识、注册表指纹、确定的创建顺序、父级挂接、属性操作、三类顺序、布局、资源、事件及启动动作。第四阶段只扩展操作种类与执行器。

设计模式构建器、预览构建器及代码生成器消费同一计划。它们可以使用不同执行方式，但不得各自定义另一套属性含义。对每个内置适配器编写预览与导出的一致性测试。

构建顺序为：创建根窗口及工作区 → 按父子顺序创建控件 → 应用非几何基础属性及数据 → 创建和填充布局 → 应用自由几何和层叠 → 设置制表顺序 → 连接事件 → 应用运行时可见性 → 显示窗口 → 执行定时器启动等动作。

导出目录包含：

| 文件 | 内容与更新规则 |
| --- | --- |
| `main.py` | 一次安装的稳定入口，读取一次版本指针后运行该完整版本 |
| `current.json` | 当前完整生成版本及文件摘要；唯一发布点 |
| `generated/版本标识/ui_main.py` | 窗口类、`setup_ui()`、控件创建、属性、布局及事件适配 |
| `handlers.py` | 用户处理函数；首次创建，后续保留已有文件 |
| `generated/版本标识/assets/` | 此版本自己的资源，不引用另一个版本目录 |

导出到全新的版本目录，先完成所有文件、语法检查及资源摘要核对，再替换 `current.json`。旧版本保持不变；中途失败不能更新指针。稳定入口与业务文件不参与每次导出的覆盖操作，入口协议升级必须作为单独迁移处理。第一轮安装尚未发布版本时，入口给出中文“尚无完整生成版本”提示。

字符串通过安全的 Python 字面量编码输出，保留中文并正确处理引号、换行和路径。模板采用标准库及内置生成逻辑，不引入第三方模板库。

普通预览由独立进程从传入的文档快照和资源清单构造窗口，不必生成 Python 文件。设计器与预览之间使用版本化消息，包含就绪、错误和结束状态；启动超时或进程异常只结束该预览任务。关闭预览会释放窗口及所属定时器。进程隔离改善故障边界，但不宣称是对插件代码的安全沙箱。

“运行生成代码”使用 `QProcess` 启动当前 Python 解释器，工作目录设为导出目录，显式使用 UTF-8 捕获输出并显示中文运行状态。进程结束后清理引用；错误定位到生成文件或缺失组件。

绝对布局提供固定逻辑像素定位，不能自动推断窗口缩放时的自适应布局。需要随窗口伸缩时，应显式选择水平、垂直或网格布局。跨系统字体和原生样式差异也不承诺逐像素一致。

## 十四、资源、插件与设置

资源导入后按内容摘要命名并去重，清单只保存相对路径。尚未保存的文档使用可恢复的会话资源目录，不能仅依赖退出时自动清空的临时目录。首次保存或另存为先完成目标资源副本，再发布目标项目清单。

项目资源路径相对项目文件所在目录解释；导出资源路径相对本次读取的生成版本目录解释，即 `generated/版本标识/`。稳定入口先读取一次指针并固定该目录，界面代码和资源都使用它，不能按当前工作目录或入口文件所在目录猜测资源位置。避免保存盘符和源文件的绝对路径。导入失败或资源迁移失败时不提交新项目路径。

缺图时使用中文占位说明并记录具体资源名。资源清理必须同时检查当前项目、备份、恢复快照、正在保存的快照及撤销历史引用；不能只根据当前画布判断文件无用。本阶段不自动删除孤立资源，清理算法通过回归后再启用。

插件公开 `register(registry)` 注册入口，提供类型标识、协议版本、中文元数据、创建工厂、设计预览能力、运行时构建能力及代码导出能力。类型标识使用命名空间，重复注册必须报错。

项目加载只引用已启用的类型，不根据项目中的类路径自动导入或执行插件。外部插件需要用户安装并启用。缺少设计预览能力的特殊控件可以提供替身；缺少导出能力时明确限制导出，不能输出不可运行的半成品。

内置控件导出只依赖 PySide6 和标准库。外部插件若需要额外运行库，必须在插件说明和导出清单中声明，不能偷偷加入依赖。

用户偏好用 `QSettings` 保存默认目录、近期文件、主窗口停靠布局和新文档默认设置；文档内保存自身的网格、吸附、辅助线和模板标识。全局设置变更不追溯修改已打开的文档。

标准库除需求列举模块外，会按需使用 `uuid`、`enum`、`os`、`tempfile`、`shutil`、`hashlib`、`keyword`、`ast`、`importlib` 和 `sys` 等；它们不增加第三方依赖。

人工验收步骤：

1. 启动后看到全中文主窗口、新文档画布和组件箱。
2. 将“按钮”“标签”拖到不同位置，落点与预览一致；双击组件在可见区域中心创建。
3. 选中并移动控件，在属性面板修改名称及标题或文本，画布立即更新。
4. 创建、移动、属性修改可连续撤销重做；一次拖动只撤销一次。
5. 保存中文路径的 `.uipro`，再次保存出现备份；关闭并重新打开，控件还原。
6. 同时打开两个文档，切换标签后撤销仅影响当前文档。
7. 打开损坏项目得到中文提示，当前已打开文档仍然可用。
8. 保存期间继续编辑，旧快照写盘成功后当前文档仍显示未保存；撤销回写盘状态后恢复已保存。
9. 写锁冲突、外部文件变化和恢复快照存在时显示明确中文入口，不能自动覆盖较新的用户文件。

自动验收：生产模型、命令、存储和构建执行器通过对应契约回归；基础画布通过坐标、输入、缓存恢复以及手势性能门槛。离屏通过后仍要记录真实桌面测试结果。

已知限制：仅保证按钮和标签闭环；已提供只读对象树与画布查看缩放，尚无对象层级重排、缩放手柄、多选、事件执行、代码导出及资源管理界面。第一阶段示例中的定时器保留数据并提示不支持，本阶段建议使用《第二阶段示例.uipro》。
