# 0.10.2 迭代与验证

本轮针对导出稳定性、对话框生命周期、窗口退出和标签栏刷新修复已复现的缺陷。项目格式、组件注册表和现有业务入口保持兼容。

## 导出与启动

保存并重新打开含表格、超级列表框或表格视图的项目后，未修改内容的重复导出会复用同一版本。生成器递归整理字典键顺序，同时保留列表和元组顺序；调整表格行顺序仍会产生新的导出版本。

导出程序遇到缺失事件文件、语法错误或缺少对应函数时，会报告原始错误，并在 Qt 处理延迟删除时释放已创建的窗口、子控件和事件模块。修复业务文件后可以再次创建窗口。稳定入口 `main.py` 未改动，已有导出目录可以继续发布新版本；已有 `handlers.py` 和事件业务文件按原规则保留。

## 对话框和窗口退出

通用对话框的文件单选、多选、保存、目录、颜色和字体六种模式共用新的清理逻辑。完成时先读取返回值、解除旧窗口归属，再通知业务回调；回调可以立即重开对话框或销毁窗口。旧窗口迟到的完成信号不再影响新窗口。

外部销毁对话框后可以重新打开。配置或打开失败时清理已创建的原生对象，清空上次结果并报告取消。`dispose()` 用于静默释放，不再触发取消回调，避免退出过程中重新打开窗口。

文件选择仍返回路径列表，颜色返回颜色字符串，字体返回含“字体、字号、粗体、斜体”的字典。新的打开操作会清空 `result`，业务应使用接受信号传入的值保存已完成操作的结果。

关闭运行窗口后，下一轮事件处理会释放通用对话框和高级窗口组件并停止项目时钟。若关闭请求被业务处理函数取消、主窗口仍然显示，则保留当前对话框和时钟。清理检查的计时器归属于主窗口，窗口销毁时一同释放。

## 标签栏刷新

独立标签栏组件只在设计项目中的标签列表发生变化时重建内容。仅修改外观或父窗口颜色时，保留当前选择、运行时拖动顺序以及 `tabData()` 中的业务数据，避免重复创建标签。

显式修改初始选中项仍会应用新索引，但不重建标签。应用设计属性时屏蔽中间切页信号，并恢复原有信号屏蔽状态；运行时调用 `setCurrentIndex()` 和用户切页仍正常发出事件。本项针对独立标签栏，不改变选择夹页面结构。

## 验证与使用

新增 33 项回归用例；修复前分批保留了 19 个失败用例的输出。346 项相关回归和 1296 项完整回归全部通过，无失败、错误或跳过。源码指纹、Windows 运行验证和启动截图见 [验证记录](../reports/iteration-0102/README.md)。

运行 `python -X utf8 main.py` 使用 0.10.2 源码。已有导出程序需要重新导出才能获得修复。本轮未重建 Windows EXE。

```powershell
python -X utf8 -m pytest -q --tb=short --junitxml=reports/iteration-0102/pytest.xml
python -X utf8 -m scripts.check_iteration_0102
python -X utf8 main.py --smoke-test --screenshot reports/iteration-0102/startup.png
```

运行检查使用临时项目和临时业务文件，不改写用户演示项目。在 Windows Qt 后端和 `python -I` 隔离导出进程中，各执行 72 次对话框回调重开、50 次标签属性刷新，并检查导出失败清理、修复后重试、保存重开后的版本复用和窗口关闭后的资源释放。对话框选用 Qt 实现，以便自动驱动；本轮未覆盖 Windows 系统文件选择器的全部交互。
