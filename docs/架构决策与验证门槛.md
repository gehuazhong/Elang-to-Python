# 架构决策与验证门槛

本文件与《第一阶段架构方案（第二版）》配套，规定实现不能绕过的边界。用户确认后已实现第二阶段骨架；本文件同步选型变化，最新运行证据见《第二阶段实现与验证.md》。

## 一、推进原则

已发现的设计缺陷必须修正并有对应回归；尚未证明的技术选择保留为候选。参考程序验证成功，只代表相应契约和实验场景成立。第二阶段的生产实现须重新通过相同语义测试，不能把参考程序的通过记录当作生产代码的验收。

下列情况必须先修复当前层，暂停依赖它的功能扩建：

- 对象归属、顺序、几何、引用或撤销历史出现不一致。
- 保存失败覆盖了有效旧文件，或一次启动读取了不同生成版本的文件。
- 手势取消后留下隐藏控件、错误布局或过期画面。
- 画布只在简单按钮场景正常，尚未通过实际要支持的输入和缩放检查。
- 性能结果超过约定门槛，却通过减少样本、删去异常帧或放宽指标来宣布通过。

代码目录沿用现有模块边界，不引入额外服务、通用消息平台或新的第三方基础设施。只有实际解决问题的接口和状态才进入架构。

## 三、顺序模型与第二版格式

所有节点保存 `parent_id`、`slot` 和 `object_order`。普通可视兄弟节点额外保存 `stack_order`；受容器布局管理的节点保存 `layout_item.index`。其余节点的层叠和布局项为空。

| 操作 | 可以改变 | 必须保持 |
| --- | --- | --- |
| 对象树内排序 | `object_order` | 几何、层叠、布局位置、制表顺序 |
| 上移一层、置顶 | `stack_order` | 对象树、布局位置、制表顺序 |
| 水平或垂直布局插入 | `layout_item.index` | 对象名称、标识、层叠 |
| 网格布局插入 | 布局项的行列和跨度，必要的稳定索引 | 对象身份及无关层叠 |
| 制表顺序编辑 | `tab_order` | 对象树、绘制和布局 |
| 改变父级 | 两边相关序列、父级、挂接位置、坐标及布局项 | 未参与操作对象的身份和无关状态 |

各序列在自己的作用域内从零开始、唯一且连续。网格索引用于稳定构建，行列决定实际位置；不能把二者的作用混淆。

当前文件格式为 `schema_version = 2`。第一版迁移只在副本上执行，保留对象身份和扩展数据；三种新顺序从旧字段初始化，随后独立工作。未来版本不允许猜测性降级。尚未建立迁移函数和往返测试时，不得改已发布格式。

对象树是模型投影。Qt 的子对象列表可能受层叠操作影响，因此不作为对象顺序的存储来源。Qt 控件坐标与布局计算结果同样不能反向覆盖模型中的自由布局参数。

参考实现：`architecture_checks/contracts.py`。对应测试：`test_stack_change_keeps_object_and_layout_order`、`test_migration_is_pure_and_repeatable`、`test_raise_does_not_change_layout_order`。

## 四、文档事务、撤销与保存点

### 4.1 状态身份

`revision` 是会话中的单调修订号，每次实际提交、撤销和重做都递增，用来拒绝过期任务。`state_id` 标识一个历史状态，撤销可以回到旧状态标识。二者不能互相替代。

`saved_state_id` 标识实际写入项目文件的状态。未保存状态定义为当前状态标识与它不同。相同内容通过另一条编辑路径得到不同状态标识时，允许仍显示未保存；不为此对每次键入计算整个文档摘要。

### 4.2 正常提交

1. 交互控制器记录基础修订号、目标节点和用户意图，不持有可写模型引用。
2. 准备阶段检查版本、锁定状态、结构、属性类型、引用和布局约束。
3. 创建前后状态及不可变变更集；可能失败的插件校验、资源准备和外部读写在压栈之前结束。
4. 候选结果无效时，当前模型、历史游标、重做分支、已保存身份和选中状态保持不变。
5. 候选结果与当前内容相同，不创建空历史项。
6. 命令压栈；`redo()` 只切换已经准备的数据，不再调用文件系统或插件工厂。
7. 历史操作返回后发布一次变更集，面板读取新的只读快照。
8. 监听失败记录中文错误并触发该视图重建；其他监听者仍获得通知。

准备与通知期间均禁止同步重入编辑、撤销、重做、开始保存和处理保存回执。否则外层候选仍基于旧快照，内层修改可能被覆盖，或者失败操作会改变保存身份。临界区采用异常安全的状态保护，准备失败保留原历史、重做分支和待完成保存票据，并在退出后恢复正常操作。

需要由变化触发后续操作时，在下一轮事件循环重新取得快照和修订号后发起；保存回执也排队交由会话处理。准备、提交及快照抓取的临界区禁止主动调用 `processEvents()`。

生产实现采用受影响分支的快照与差异，不能每次鼠标移动复制整棵项目树。本阶段 `ReferenceHistory` 特意使用完整 JSON 字节快照来验证语义，不应被直接当作生产性能实现。

### 4.3 撤销与资源

删除、粘贴、父级调整和布局转换必须持有完整逆操作所需数据，包括关联连接、处理函数声明和资源引用。大操作作为一个命令提交，禁止半棵子树进入文档。

历史使用独立 `CommandHistory`，每文档默认六十四兆字节的保留数据预算。当前计量为变化节点与元数据序列化后的 UTF-8 字节数，是确定性的保留负载上限，不等于 Python 对象、映射或 Qt 的进程内存上限。达到预算后裁剪最旧的完整命令；单次超预算在提交前拒绝，保持当前状态及重做分支。实际进程内存另行测量，物理内存的严格预算需要后续专门实现。

### 4.4 保存回执

保存票据包含会话标识、捕获修订号、状态标识、只读内容、目标路径及预期磁盘摘要。同一文档只允许一个正在提交的保存任务。

例如：捕获状态甲开始保存，用户继续编辑到状态乙；甲保存成功后，当前乙仍是未保存。撤销到甲时恢复已保存。保存失败不改变已保存身份。其他会话、已结束任务和重复回执不能更新当前状态。

第二阶段使用独立历史，不维护 `QUndoStack.setClean()` 的第二套状态。菜单、快捷键和工具栏统一调用文档会话，保存票据只更新实际落盘的状态身份。输入框具有焦点时，文字撤销优先。

## 五、项目与资源的提交协议

### 5.1 单一发布点

项目文件是一个 JSON 清单，资源文件是不可变内容。资源名使用内容摘要，改变图片内容意味着生成新的文件，不覆盖旧资源字节。

提交步骤：

1. 对目标规范路径取得 `QLockFile` 写锁。相同应用中的重复打开定位到既有文档；另一个写者取得锁失败时只能只读打开或另存。
2. 捕获只读快照及上一次读取的项目原始字节摘要。
3. 检查所有资源，新增资源写入目标目录的暂存文件，刷新缓冲并同步文件后替换到摘要路径。
4. 已存在的摘要路径必须再次核对内容，不能假设同名文件一定正确。
5. 确认所有新清单引用的资源已完成；再次检查原项目摘要没有外部变化。
6. 将旧项目字节写入独立暂存备份，再替换 `.bak`。旧资源继续保留。
7. 新清单写入同目录暂存文件，刷新并同步后，最后替换项目文件。
8. 依据预先计算的新清单摘要返回回执；更新磁盘身份，按票据更新保存状态。

项目清单替换前中断，当前项目仍使用旧资源；替换后中断，新项目所需资源已经存在。孤立的新资源可以留下，但不能出现在一个尚未完整发布的项目引用中。

使用同目录暂存保证同一文件系统。替换失败必须明确失败，不允许退回到打开原文件直接截断写入。

### 5.2 锁与外部修改

写锁协调遵守本协议的写者。摘要检查发现编辑器外部的改动时停止覆盖，提供重新打开或另存副本的中文选择。

摘要检查与文件替换并不是对所有外部程序的通用比较交换操作；不遵守写锁的程序仍可能制造竞争。首版不会声称支持多个任意工具同时改写同一项目，也不把未经验证的网络共享盘纳入强一致性承诺。

### 5.3 崩溃恢复

恢复目录使用持久的用户数据目录，不能只用退出时自动清空的临时目录。每个文档、会话隔离；快照携带独立资源副本，项目原路径失效时仍能恢复。

默认在停止编辑两秒后安排快照，连续编辑时最长十五秒安排一次。只记录已提交模型，不保存尚未释放的鼠标手势。调度任务接收只读快照，使用与正常保存相同的资源和清单协议。

启动后展示恢复时间、来源项目和可恢复内容，用户选择后打开为未保存副本。恢复不能自动覆盖来源项目；只有用户明确保存到目标位置时才重新检查写锁和磁盘摘要。

快照和资源清理需要同时追踪当前文件、备份、恢复版本、在途保存与撤销历史。首版不自动清理孤立资源；清理算法另行通过回归后再启用。

本轮真实进程退出验证发生在 Windows 本地文件系统上。它证明被测提交顺序的进程中断行为，不是硬件断电、介质损坏或任意网络文件系统的耐久性认证。

## 六、生成代码的版本发布

导出目录约定：

```text
导出目录/
├── main.py                         稳定入口
├── handlers.py                     用户业务文件
├── current.json                    当前完整版本指针
└── generated/
    ├── 旧版本标识/
    │   ├── ui_main.py
    │   └── assets/
    └── 新版本标识/
        ├── ui_main.py
        └── assets/
```

每次生成使用新的版本目录。Python 语法、导入需求、事件签名及资源先完成检查；所有文件就绪后才发布新指针。入口只读一次指针，从同一个版本目录读取所有界面文件和资源。生成资源中的相对路径以该固定版本目录为基准，不依赖入口目录或启动时的工作目录。

稳定入口及其加载协议在首次导出时安装。首次安装没有完整指针时只显示中文错误；不会运行半个版本。正常界面更新不覆盖入口，入口协议升级是单独迁移，不能混进普通导出。

`handlers.py` 首次创建后归用户所有。后续生成不得替换它、截取代码区域重写或假定用户函数签名没有变化。新增事件可以使用生成侧的中文默认处理器，同时报告待实现签名；已有函数不兼容时必须报告具体事件，不静默断开。

旧生成版本保持完整，首版不自动删除。用户运行外部导出程序时可能仍在读取旧资源，不能只看当前指针就认定旧目录无人使用。

早期发布实验仅验证版本切换和字节完整性。0.3.0 已对按钮、标签、单行编辑框及窗口属性实现完整生成器、稳定入口和业务入口签名检查；已增加原生属性差分、仓库外独立运行、故障注入与业务文件保护验证。资源、自定义事件配置及自动布局尚不在导出范围，具体证据见《商业化基础与验证》。

## 七、最小构建计划提前落地

第二阶段必须先实现按钮、标签、根窗口和工作区的计划编译与执行，随后再接入组件箱。画布不能先拥有一套独立的属性解释代码，第四阶段再尝试统一。

`BuildPlan` 的输入是文档快照和冻结注册表。它记录协议版本、源状态身份、注册表指纹和明确类型的操作；不保存 QWidget、信号实例、可调用对象或任意求值表达式。

初始操作仅包括创建、挂接、设置属性、应用几何、层叠及运行时可见性。第三、四阶段添加布局、集合数据、事件、资源和定时器启动操作。每种操作具有已注册适配器，不开放任意方法名称执行。

执行顺序遵守依赖：父级先于子级，范围先于当前值，控件先于布局项，初始化先于事件连接，绑定完成先于定时器启动。显式对象顺序、层叠、布局和制表顺序不能在生成时混用。

相同快照、注册表和模板应得到稳定计划及确定性代码。验证比较原生构建与导出构建的对象结构、关键属性、布局成员、信号效果和资源引用；不能只比较代码是否能够通过语法编译。

第二阶段须完成的检查：

- 在不创建窗口的情况下编译最小计划。
- 属性面板、画布构建与导出准备使用同一元数据转换函数。
- 不支持的组件或适配器在构建前明确报告。
- 相同输入反复编译保持顺序及结果稳定。
- 计划没有 Qt 运行时对象，读取模型不会产生副作用。

## 八、画布候选方案及手势缓存

### 8.1 可替换边界

`CanvasRenderer` 对外提供应用快照或变更集、查询节点矩形、坐标转换、命中测试、准备手势、绘制临时状态、取消及释放。它消费稳定节点标识，不能反向修改文档。

第二阶段使用真实 QWidget 树生成控件缓存，由独立图元按显式层叠顺序合成；手势不重新抓取整个窗口，也不隐藏原生控件。根代理只保留在比较实验中。新增复杂容器、布局与特殊控件必须重新验证裁剪、显示和输入，文档与命令层不得依赖具体绘制路径。

### 8.2 三段时延

第二阶段在稳定状态准备独立控件画面；按下记录原位置，拖动时只更新临时图元矩形，松手后一次提交。准备、连续帧、最终提交仍分别计量。以下隐藏原生控件的约束保留给采用背景抓取的复杂控件适配器，本阶段缓存图元路径不需要执行该隐藏步骤。

隐藏控件以抓取背景时，必须临时保留其在父布局中的尺寸，否则会改变其他控件位置。恢复时还原原有尺寸策略、可见性和绘制启用状态；重复取消或结束不能再改变它们。

父子同时被选中时只抓取最上层子树。临时画面按显式层叠顺序合成，并遵守父容器裁剪、滚动区域及目标容器边界。高分辨率图像和坐标必须使用一致的设备像素比。

文本、字体、样式、资源、可见性、容器、画布缩放或设备像素比变化都要使缓存失效。快照依赖的状态身份变化时取消手势，不允许继续把过期画面提交到新模型。

### 8.3 实验能证明什么

离屏实验比较代理重绘、控件直接绘制、二十个临时快照合成三种路径。每组独立进程，五次预热、六十次正式测量；规模为一百、五百、一千个混合控件。快照准备时间单列，所有原始结果保留。

快照实验的输入层还不是完整设计器。它不能证明滚轮、组合框弹出、菜单、输入法、跨容器裁剪或跨屏缩放已经正确。像素与布局保持测试只证明被测画面确实移动、模型几何未被临时改变，并能恢复原始显示。

在完整画布中，冻结的是原生背景绘制层，临时合成层保持独立可绘制；不能把整个最终视口禁用后宣称手势已经完成。本阶段基准在独立图像目标上合成，明确保留这一集成检查。

## 九、线程、对象生命周期与预览

GUI 对象、字体与样式解析、控件创建和绘制适配由界面线程执行。文件读取、摘要、JSON 处理和资源复制可以在后台执行，只接受不可变输入；后台回执携带会话、任务和状态身份。

大型构建分批执行，并允许取消；主线程每批目标预算为八毫秒。取消后不发布部分控件树。替换旧树时，先构建新树并核对成功，再交换显示，最后销毁旧对象。

所有控件的 Qt 父级、Python 引用表和释放顺序明确归属于一个运行时树。预览关闭时先停止所属定时器，再断开桥接引用并释放窗口。过期任务不能向已关闭文档写入面板状态。

预览使用独立进程，接收版本化文档快照及资源位置，返回就绪、中文错误和退出信息。启动超时、异常退出和用户关闭只处理该任务。首次实现就包含启动失败、重复关闭和重新预览测试。

当前基础预览已实现并通过 32 项专项回归，复用同一构建计划及属性适配器。资源属性与外部插件尚未接入，具体边界及实测记录见 `预览功能与验证.md`。

插件注册表在会话中固定。启用或升级插件不得在打开文档中途替换已有类型的属性语义；需要版本迁移和重新构建。设计器中执行的原生插件仍属于可信扩展，独立预览进程不等于完整插件沙箱。

## 十、量化验收目标

以下是下一阶段的目标，不是对本轮实验的成绩重命名。参考机记录在结果文档；换机器须重新建立基线。连续交互的分位数计算不删除异常帧，冷启动和首次手势另外记录。

| 指标 | 一百个控件 | 五百个控件 | 一千个控件压力场景 |
| --- | --- | --- | --- |
| 连续手势第九十五百分位 | 不超过十六点七毫秒 | 不超过十六点七毫秒 | 不超过三十三点三毫秒 |
| 首次手势准备 | 不超过五十毫秒 | 不超过五十毫秒 | 不超过一百毫秒 |
| 最终提交到稳定画面 | 不超过五十毫秒 | 不超过一百毫秒 | 不超过一百五十毫秒 |
| 单个常规命令或撤销响应 | 不超过五十毫秒 | 不超过五十毫秒 | 不超过一百毫秒 |
| 项目加载到可编辑 | 不超过一秒 | 不超过一秒 | 不超过两秒 |
| 自动保存的主线程准备 | 不超过八毫秒 | 不超过八毫秒 | 不超过八毫秒 |

保存总耗时取决于资源大小，不能把大文件写盘时间全部计为界面阻塞，也不能把耗时复制隐藏在所谓瞬间保存后面。分别记录捕获、资源准备、清单提交与回执时间。

内存记录进程私有内存和历史保留量。经过预热后，循环创建、关闭十轮同等文档，检查对象是否销毁及占用是否稳定；持续增长时先定位引用和原生对象，不能靠定时清空缓存掩盖泄漏。

若准备阶段超过门槛，优先检查重复绘制、过期缓存与不必要的整树处理。可以在文档稳定时提前准备可复用内容，但缓存有效性必须经过状态身份和显示参数校验。不得通过放宽门槛隐去回归。

## 十一、生产推进门槛

| 门槛 | 必须具备的证据 | 未满足时的处理 |
| --- | --- | --- |
| 契约门槛 | 格式版本、顺序分离、迁移、提交失败、保存身份的回归 | 先修正模型与协议 |
| 存储门槛 | 写锁、外部修改、文件失败、进程中断、独立恢复副本 | 不开放覆盖保存与自动恢复入口 |
| 构建门槛 | 最小计划、唯一属性解释路径、确定性和错误定位 | 不扩充组件类型 |
| 画布门槛 | 命中、坐标、缩放、输入拦截、像素、取消、布局保持及性能 | 只修复验证画布，不扩建编辑功能 |
| 实机门槛 | 真实鼠标、百分之一百至百分之二百显示缩放、中文输入、菜单及组合框 | 不宣布完整画布选型通过 |
| 发布门槛 | 生产命令和存储重新通过契约；真实预览与导出一致 | 不宣布产品可交付 |

本轮的契约实验通过后，可以据此实现第二阶段的验证性骨架。它没有解除构建、完整画布、实机和产品发布门槛。
