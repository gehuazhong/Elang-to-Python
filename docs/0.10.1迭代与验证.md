# 0.10.1 迭代与验证

本次改进集中在整组复制、对话框生命周期与大型界面的构建计划耗时。项目文件格式和组件注册表指纹不变，已有 `.uipro` 项目继续使用。

## 整组复制与对象树

在对象树中按住 Ctrl，依次点击多个时钟、输入对话框、进度对话框等非可视组件，可以整组复制、粘贴或删除。多个停靠窗口也支持上述操作，容器中的子控件随容器一起复制。粘贴和删除各作为一次操作撤销、重做。

画布控件、非可视组件、停靠窗口分别多选；主窗口、工作区、页面和窗口条保持单选。非可视组件的多选属性区显示组件类型，不提供位置排版。

复制时遵循以下规则：

- 按钮与其触发的对话框一起复制，副本对话框关联副本按钮；启用“接受”等事件后仍可复制。
- 未包含在复制范围内的触发按钮、导航页面和按钮组成员会解除关联，并在状态栏显示跳过数量。
- 事件声明与组内连接随副本保留；代码名称与已有组件、事件函数名称避重。
- 事件函数的外部业务代码仍需自行维护，不会通过剪贴板复制。

非可视组件粘贴后属于目标项目的主窗口，不产生画布位置或层级数值；锁定主窗口时禁止粘贴。

## 对话框与进度任务

输入对话框的接受、取消回调中可以立即调用 `open_dialog()`，新的对话框不会再被上一轮关闭逻辑清除。结果取自实际打开窗口的输入模式，避免配置更新后错误读取结果。

进度对话框通过服务的 `setValue(value)` 更新。在到达设定最大值时，每次打开的任务只报告一次完成；取消按钮、Esc、关闭和拒绝均只报告一次取消。旧窗口后续的关闭信号不会影响回调中打开的新窗口。

“自动关闭”和“自动重置”四种组合均有覆盖。完成后再次打开会创建新任务，并恢复设计时设定的初始进度；自动关闭禁用时，已完成的窗口可以保留显示。范围为 `(0, 0)` 的忙碌状态不会误报完成，超出范围的更新沿用 Qt 的忽略行为。

取消后尚未重新打开时，迟到的进度更新会被忽略。如果业务同时管理多个异步任务，仍应在业务层区分任务标识，避免旧任务更新正在运行的新任务。

运行时、正式 F5 子进程以及独立导出使用相同的实现。本次源码升级不会自动更新以前导出的程序；重新导出到原目录即可使用修复后的运行模块，已有业务文件按原有规则保留。

## 性能与兼容性

组件默认属性改为缓存不可变快照；普通字符串、整数、布尔值和有限浮点数采用直接转换路径。仍拒绝非有限数字、非法键名和不支持保存的对象；修改一个实例的属性不会污染其他实例或注册表。

使用同形状的 500 个按钮项目、两次预热和七次采样测量 `compile_plan`。优化前中位数为 195.101 毫秒，最终源码为 76.862 毫秒，本机采样降低约 60.6%；原始采样值与源码指纹见 [性能报告](../reports/iteration-20261111/performance-after.json)。该指标只反映构建计划阶段，不代表完整启动、渲染或导出的耗时，也会受机器负载和缓存状态影响。

验证环境为 Windows、Python 3.11.8、PySide6/Qt 6.11.1、pytest 8.3.4。本次不重建 Windows EXE，不更改原有 07、08 演示项目。
