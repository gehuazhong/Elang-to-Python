# 第二阶段实现与验证

记录日期：2026 年 11 月 6 日。

## 一、交付范围

已提供可运行的中文设计器骨架：中文菜单与工具栏、搜索组件箱、多文档画布、按钮和标签的 MIME 拖放及双击创建、单选移动、中文属性面板、只读对象树、输出面板、撤销重做、保存加载、写锁及自动恢复。

画布支持查看缩放、显示网格和网格吸附；可通过属性修改位置与尺寸。文字和数值按回车或离开输入框提交，布尔与枚举选择即时应用。每次完整移动只产生一个撤销项，按退出键取消。文本输入框具有焦点时，文字编辑快捷键优先。

这是第二阶段骨架，未扩建第三、四阶段功能。对象树尚不能重排，多选、框选、缩放手柄、复制粘贴、对齐辅助线、自动布局、事件面板、代码生成、预览运行及资源管理界面仍未交付。

## 三、启动与检查命令

在项目根目录执行：

```powershell
python -m pip install -r requirements-dev.txt
python -X utf8 main.py
```

也支持 `python -m app`。根目录的 `main.py` 复用 `app/__main__.py` 中的启动函数，日志、异常处理和初始化保持统一。

只有运行需求时，安装 `requirements.txt` 即可。当前验证环境为 Python 3.11.8、PySide6 6.11.1、Qt 6.11.1、pytest 8.3.4；没有新增其他第三方依赖。

完整回归：

```powershell
python -X utf8 -m pytest -q
```

独立检查：

```powershell
python -X utf8 -m tests.benchmark_canvas
python -X utf8 -m tests.check_lifecycle
python -X utf8 -m tests.check_desktop
python -X utf8 main.py --smoke-test
```

画布与生命周期检查使用离屏平台。桌面检查使用实际 Windows 平台插件，短暂打开测试窗口并自动关闭，项目保存测试在独立临时目录进行。报告命令会更新对应报告文件；历史结果使用不同文件名保留。

## 四、实现中的关键约束

### 数据和历史

节点使用不可变数据类，属性、扩展数据及元数据递归冻结。快照共享未改变的节点，命令只保存受影响节点和必要元数据。名称、顺序、几何、引用或属性无效时，候选修改整体拒绝。

第二阶段采用独立 `CommandHistory`，以适应按保留负载裁剪的要求。每文档默认预算为 64 兆字节，计量变化数据的 UTF-8 序列化字节数；这不是进程实际内存的硬上限。单命令超预算会在提交前被拒绝，不丢弃原历史及重做分支。

准备和通知期间不允许重入编辑、撤销重做或保存状态操作。修订号递增；保存状态绑定历史身份。旧快照保存成功不会把后来的编辑标成已保存。

### 保存与恢复

写锁协调本应用的写者，外部文件摘要变化会阻止覆盖。资源先写入内容摘要路径，旧清单写入 `.bak`，新项目清单最后替换。只读打开可以另存为新项目，成功后恢复编辑。

文件写入在后台执行；保存票据捕获不可变模型。关闭保存中的文档会等待结果，保存失败保留文档。保存成功后若有新修改，文档保持打开。保存完成通知不会清空属性输入框中尚未提交的文字。

恢复副本位于 Qt 用户数据目录的“恢复副本”子目录。停止编辑两秒或持续编辑最长十五秒安排一次快照；只保存已经提交的模型。恢复清单使用独立资源副本，打开后是未保存文档，不自动覆盖来源文件。

活跃会话持有恢复目录写锁，不会被另一个实例误列为崩溃恢复记录。已成功保存的旧恢复清单归档，后续编辑仍能产生新快照。资源暂不自动清理，避免误删备份或恢复仍需的数据。

### 统一构建与画布

注册表在会话中冻结。`BuildPlan` 从模型编译出稳定的节点与属性计划，原生构建器负责反射与枚举转换，属性面板不另写 Qt 属性赋值规则。标签明确使用纯文本。

原生控件用于生成外观缓存；场景中的独立图元负责绘制和移动，按显式层叠顺序合成。拖动过程中不修改模型和 QWidget 几何，释放时再提交一次命令。查看缩放和设备像素比变化会重新生成相应缓存。

超过一百个节点的首次控件构建和缓存准备分批完成，每批工作循环使用约六毫秒，为 Qt 操作和发布留出余量。准备期间暂停编辑，可关闭标签取消；全部完成后一次发布，不显示部分控件树。批次预算是调度目标，不能抢占正在执行的单个 Qt 调用。

Qt 元对象包装只在探针或所属实例有效时使用，避免跨实例销毁保留失效包装。实际主窗口使用明确的浅色配色，避免系统深色配色与浅色面板混用。

## 五、自动化结果

完整回归实际输出：**110 项通过，耗时 7.20 秒**。其中 60 项针对第二阶段实现，50 项为第一阶段参考实验。

当前实现覆盖以下路径：

- 数据不可变、扩展字段往返、旧格式迁移、未来格式拒绝、顺序独立。
- 候选失败、准备重入、监听失败、过期保存身份、历史预算、250 次编辑的完整撤销重做。
- 生产项目保存的七个真实进程中断点、文件替换失败、外部修改、资源缺失、独立副本及写锁。
- 注册反射、纯文本标签、四档画布缩放下的坐标和单次手势提交、退出键取消、透明叠放和输入拦截。
- 分批构建时允许事件循环继续工作，取消后释放尚未发布的原生控件。
- 属性和对象树联动、多文档隔离、输入框快捷键优先、切换标签提交文字、保存回执保留正在输入的文字。

生命周期检查先做三轮预热，再连续观测四十轮，每轮一百个控件。43 个原生根窗口全部收到销毁信号。初期私有内存增长，后段明显趋缓：最后十轮在 45,064,192 至 45,174,784 字节之间。另一次延长探针结束时，Qt 存活控件数量为零，未发现仍受 Python 垃圾收集器跟踪的画布、运行时树或文档实例。

完整序列保存在 `reports/第二阶段生命周期.json`，早期及延长观察分别保留。读数呈现预热后趋稳的行为，不能据此声称没有任何长期泄漏，也没有使用定时清空 Qt 缓存掩盖问题。

## 八、人工验证步骤

1. 启动应用，从左侧拖入“按钮”和“标签”，确认落点；双击组件可在当前可见区域创建。
2. 选中按钮，在属性面板修改名称、标题、位置或尺寸，按回车；检查画布和对象树同步。
3. 移动控件后撤销一次，位置应恢复；拖动中按退出键，不应新增撤销项。
4. 输入框中选择文字并按删除键，确认没有删除画布控件；按撤销只撤销文字编辑。
5. 新建第二个文档，分别编辑、切换并撤销，确认只影响当前文档。
6. 保存为中文路径的 `.uipro`，修改后再保存，确认同目录出现 `.uipro.bak`；关闭再打开后内容一致。
7. 打开 `examples/第二阶段示例.uipro`。第一阶段完整示例中的定时器和事件会保留，但不会执行。
8. 在第二个应用实例打开已被占用的项目，确认只读提示；另存为新路径后可以编辑。
9. 有恢复记录时使用顶部提示或“工具 → 恢复项目”，确认恢复结果未覆盖原项目。

## 九、明确限制

本阶段只编辑绝对布局。自动布局项目会在打开前被拒绝并给出中文原因，已有文档不被清空。缺失类型使用占位或中文提示，原始数据继续保留；这不表示已支持其运行行为。

单个项目文件当前限制为 32 兆字节，控件宽高范围为 1 至 16384，单张绘制缓存不超过 16,777,216 像素。未知扩展、资源、事件数据可保留，但没有对应编辑器。资源缺失或篡改时停止保存，不悄悄丢弃引用。

画布缩放只改变查看方式；缩放手柄和多选几何编辑尚未实现。“可见”保存运行时语义，设计画布继续显示该对象以便选择；设计隐藏属于后续编辑功能。

当前没有最终产品安装包、完整预览、代码生成或外部插件加载器。后续阶段仍须经过既定构建、复杂画布、真实桌面和发布门槛，不能直接把本次基础回归视为整体产品已验收。
