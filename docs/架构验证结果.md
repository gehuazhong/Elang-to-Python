# 架构验证结果

验证日期：2026 年 11 月 6 日。

本文保留第一阶段第二版架构、项目契约示例与独立验证程序的历史结果。当时尚无设计器入口；第二阶段现已实现应用，当前结果见《第二阶段实现与验证.md》。本文的 50 项参考实验不直接代替生产实现验收。

## 二、自动化验证

最后一次完整执行命令：

```powershell
python -X utf8 -m pytest architecture_checks/tests -q
```

实际结果：**50 项通过，耗时 2.59 秒**。

| 测试组 | 通过数量 | 已覆盖的行为 |
| --- | --- | --- |
| 数据与事务契约 | 19 | 顺序独立、重复及网格重叠拒绝、迁移纯度、扩展保留、失败提交、过期操作、重入隔离、保存身份、撤销重做 |
| 持久化与导出发布 | 20 | 14 个真实进程中断点、替换失败、外部修改、资源缺失或篡改、恢复副本、发布路径和业务文件边界 |
| Qt 与快照行为 | 11 | 原生层叠及布局、四种画布缩放坐标、输入拦截正反对照、撤销压栈、写锁、像素移动和恢复、布局保持 |

契约测试使用固定随机种子执行 250 次编辑，随后全部撤销并重做，比较完整序列化结果。它验证这些操作的回放语义，不是通用随机输入测试或生产历史性能测试。

最终复查新增五个准备期间重入用例，分别尝试再次编辑、撤销、重做、开始保存及处理保存回执。修正前五例均未满足统一的临界区约束；修正后候选失败保持原快照、修订号、重做分支和保存票据，离开临界区后仍可正常处理保存和重做。

### 真实进程中断

测试在独立子进程执行提交，并在指定检查点调用 `os._exit(86)`，父进程核对退出码和落盘文件。没有依靠异常捕获或正常退出清理模拟进程中断。

| 提交类型 | 中断位置 | 通过数量 |
| --- | --- | --- |
| 项目 | 资源暂存、资源替换、全部资源就绪、备份暂存、备份替换、清单暂存、清单替换 | 7 |
| 导出 | 资源暂存、资源替换、界面文件暂存、界面文件替换、全部文件就绪、指针暂存、指针替换 | 7 |

被测场景在最终清单或指针替换前读取完整旧版，替换后读取完整新版；资源摘要匹配，旧资源和已有业务文件保留。提交前失败允许留下尚未引用的新资源或新生成目录。

持久化参考程序要求调用者已经取得写锁，写锁本身另有 Qt 测试。当前未实现把锁、后台任务、关闭会话及中文对话框串联起来的生产存储服务。进程退出测试也不等于断电、介质损坏或网络共享盘耐久性验证。

导出测试使用字节负载验证发布次序和完整性，负载不是完整的可运行 Python 应用。它没有验证生成器、稳定入口、用户函数签名检查或真实事件运行。

### 对实现方向的影响

本次大场景全量重绘成本明显高于连续交互目标，因此不把“每次鼠标移动都同步重绘整树”作为默认实现。快照合成值得继续集成验证，但开始准备仍有明显成本，最终提交到稳定画面的耗时尚未测量。

像素测试验证了临时画面的实际移动，以及真实控件几何未被临时移动；取消后恢复原显示。布局测试验证隐藏前保留布局尺寸、恢复原尺寸策略。这些测试比只检查接口可调用提供了更具体的证据。

现有快照在独立图像目标上合成。产品需要能持续绘制的临时层：只能冻结原生背景层，不能禁用最终整个视口。真实鼠标输入、命中、辅助线、跨容器裁剪、菜单弹出、中文输入法、跨屏设备像素比及完整手势状态机仍未纳入基准。

因此，上表不是桌面帧率、完整拖动时延或最终画布选型通过证明；不得用其宣称产品已经达到稳定帧率。

## 四、复现方法

在项目根目录执行；已安装相同依赖时可以跳过安装。

```powershell
python -m pip install -r requirements-architecture.txt
python -X utf8 -m pytest architecture_checks/tests -q
python -X utf8 -m architecture_checks.qt_probe
python -X utf8 -m json.tool "examples/中文界面示例.uipro"
python -X utf8 -m json.tool "examples/控件元数据示例.json"
```

基准命令会重新生成 `reports/画布基准.json`，实测耗时随机器负载变化。保留历史报告时应使用不同文件名，同时记录代码版本和环境；不能把后来生成的数据冒充本文这次执行的原始结果。

## 五、进入下一阶段的条件

本轮已具备顺序、提交和基础绘制实验的证据，可以按修订契约推进第二阶段的验证性骨架。以下工作必须在各自门槛内完成：

1. 生产文档、命令及存储服务重跑失败提交、重入、旧快照保存、迁移和中断回归；补齐历史预算、任务身份及生命周期处理。
2. 最小构建计划先支持窗口、工作区、按钮、标签；证明模型与注册表可确定性编译，同一属性只有一套解释规则，再扩充控件类型。
3. 完整画布分别测量手势准备、连续帧和最终提交；补齐裁剪、取消、命中、输入拦截及布局保持。
4. 在真实桌面验证鼠标拖放、中文输入、菜单和组合框，以及百分之一百至百分之二百系统显示缩放，不能用画布缩放测试替代系统显示缩放。
5. 第四阶段验证真实预览与生成代码的结构、属性、资源及事件效果一致，补齐稳定入口和业务文件兼容检查。

架构的作用是提前纠正已经发现的问题，并把未证明的选择限制在可替换、可测试的边界内。任何一项关键门槛不通过，先修复该层，不继续叠加依赖它的功能。
