# 原大画布编辑与验证

本轮版本为 0.7.1，针对设计窗口被缩得过小、居中留白过多而难以看清控件的问题。以正常尺寸拖放编辑为默认行为，查看全貌作为主动操作。界面、依赖及项目格式沿用现有实现。

## 原因与改动

此前 CanvasPage 首次显示时安排执行适合窗口。首次显示时工作台布局可能仍在变化，计算出的比例取决于当时画布大小，随后也不会恢复。同时画布采用居中显示，造成窗口缩小后周围留白过多。

现在每个新建或打开的文档从 100% 开始，窗口外框距画布左上方二十个逻辑像素。设计尺寸以 Qt 逻辑像素显示，系统高分辨率缩放仍正常生效；不会通过修改项目字体或控件尺寸掩盖查看问题。大窗口通过水平和垂直滚动条浏览。分批加载较大文档也遵守同样规则。

调整工作台大小和面板大小保持查看比例；切换标签保留各文档的比例与滚动位置。控制键加滚轮以鼠标处的内容为锚点缩放，场景边缘由滚动范围约束。普通滚轮只滚动；没有位移的滚轮事件不会意外缩小。

| 操作 | 结果 |
| --- | --- |
| 新建或打开项目 | 100% 原始大小，左上开始 |
| 原始大小、Ctrl+0 | 恢复 100%，返回窗口左上方 |
| 查看全貌、Ctrl+9 | 根据当前可见区手动缩小，便于查看整体 |
| 普通滚轮 | 滚动设计区域 |
| 控制键加滚轮 | 围绕鼠标缩放 |
| 缩放后保存或导出 | 窗口尺寸、属性与生成代码保持原值 |

旧版 Ctrl+0 对应适合窗口，本版改为恢复原始大小；查看全貌使用 Ctrl+9。原有项目不需要迁移。

## 文件与验证

| 文件 | 职责 |

| app/workspace.py | 移除首次显示自动缩小 |

```powershell
python -X utf8 main.py
python -X utf8 -m pytest -q
python -X utf8 -m tests.check_canvas_view
```

人工检查：打开设计器后确认工具栏显示“100% 原大”；拖入选择夹、编辑框和按钮，文字应按原尺寸显示。缩小整个工作台时使用滚动条浏览，点击“查看全貌”后再点击“原始大小”应返回正常比例。滚动到右下方拖入控件，位置属性应与落点一致，撤销一次移除该控件。

## 本机结果

验证日期为 2026 年 11 月 7 日。Windows、Python 3.11.8、PySide6 6.11.1；全量五百四十项测试通过，耗时一百零四点六〇秒。原大查看、画布移动、缩放手柄和外观专项九十二项通过。

原大桌面检查在设备像素比 1.0 与 1.5 下均通过；后者通过本次进程的 QT_SCALE_FACTOR 设置验证。两个场景均检查首次 100%、左上定位、小窗口滚动条、工具栏入口、实际快捷键和模型不变。报告为 reports/原大画布_100_桌面检查.json 和 reports/原大画布_150_桌面检查.json，截图使用相同前缀。

工作台、缩放手柄与易语言基础组件桌面回归均通过。源码交付检查 reports/源码交付检查_0.7.1.json 通过，包含原大查看、三十三类组件、保存加载、代码导出和独立预览。

便携包 `dist/0.7.1-20261107-053612/中文界面设计器-0.7.1-开发预览.zip` 已通过构建检查，并在仓库外重新解压、校验摘要、以仅保留 Windows 系统目录的搜索路径启动验证。报告为 reports/便携包复验_0.7.1.json。旧版便携包保留；使用可执行文件的用户需启动新包中的程序才能体验本轮修复。

本轮不修改用户已有窗口尺寸或字体；如果项目本身设置了很小的字号，仍需通过属性修改。桌面自动检查使用合成输入；启动时的不同设备像素比检查不等同于真实多显示器间移动和系统缩放切换。
